# Changelog

## 1.7.0 — 2026-10-26 (scrub is default on every burn)
- `burn` now stages the transcript cleanse automatically: the closed window's
  Hermes session id is read from `HERMES_SESSION_ID` (env, never argv) and the
  scrub plan is staged in the same breath as the shred. `--no-scrub` is the
  explicit opt-out; `--session <sid>` overrides the env id.
- Redaction marker simplified to `[REDACTED]`; the FTS residue probe now
  excludes already-redacted rows — the old marker contained the word
  "blacksite", so case-insensitive MATCH hit the marker itself and the
  verify loop could never converge.
- Scrub DB opens carry `timeout=60000`/`busy_timeout` so a running Hermes
  writer queues instead of raising "database is locked".
- `selftest_scrub.py` covers default staging via env id and `--no-scrub`.

## 1.6.0 — 2026-10-26 (transcript scrub is a tool now)
- New `scripts/scrub.py` + `incog.py burn --scrub --session <sid> [--pattern p]` and
  `incog.py scrub <id>`: the whole transcript-scrub procedure — range marker pass,
  cross-session token pass, in-place log masking, watchdog-to-clean-streak, single
  VACUUM, counts-only report, plan self-shred — is deterministic code, not per-run
  agent craftsmanship. Patterns live only in the 0600 plan file, never in argv or output.
- Two schema truths found building it: the real FTS triggers are high-water-GATED
  (updates to old rows skip reindexing — stale terms stay MATCH-able unless you
  `rebuild`), and structural id columns must be EXCLUDED from token replacement or
  the watchdog probes its own columns forever.
- `scripts/selftest_scrub.py`: sandbox-fixture E2E (fake schema w/ external-content
  FTS + triggers); wired into selftest.sh as assertion #40. Real state.db never touched.

## 1.5.0 — 2026-10-26 (destruction presumption)
- New hard rule, stated first: everything in the window is presumed to burn or be undone — task phrasing like "save it / put it on my Desktop / keep a copy" is staging, not extraction. Only the user's explicit keep-words license `incog.py keep`; ambiguity means asking BEFORE a keep, and a wrong keep is undone immediately (move back, it burns).
- Burnstep 3 rewritten to match: extraction is never agent-initiated; outbox files are handed off AFTER the burn.
- Pitfall added from first live violation of exactly this rule (anticipatory `keep` on a "save to Desktop" request, reverted same window).

## 1.4.3 — 2026-10-25 (first real scrub: three field fixes)
- Column sweeps must enumerate ALL tables/columns: the first run missed `messages.tool_calls` (paths inside tool-call JSON), `messages.reasoning` (separate from reasoning_content), and `state_meta.value` — the watchdog spun 15 min at clean_rounds=0 because of it.
- No db snapshots mid-scrub (the probe copy is itself a leak; shred it or don't make one).
- VACUUM refinement: CLI refuses under a live gateway, but a fresh connection + busy_timeout VACUUM works with the gateway idle between turns (verified twice). Added diagnose-before-looping guidance (per-target byte probes localize sweep bugs) and the results-file-close-before-self-delete rule (a log-after-close crash buried the real status).

## 1.4.2 — 2026-10-25 (transcript scrub)
- New optional post-burn procedure: scrub the window's TEXT from the agent's own records (session DB + logs) — replace-based row updates, WAL checkpoint, in-place log byte-scrubs, watchdog pattern for the "scrub must be last mention" paradox, live-VACUUM prohibition, and the self-referential-logging rule (patterns never in commands or script output). Derived from first real scrub under a live gateway.

## 1.4.1 — 2026-10-25 (live-use lesson)
- Pitfall: logging `delete` for a session-created artifact made burn RESTORE it from its own backup — resurrecting a discarded file in a persistent dir. Rule: session-created files get `create`/`other`, never `delete`; plus mid-window ledger demotion procedure (patch BOTH LEDGER.jsonl and .bak, re-verify with `burn --dry`). Caught by the standing `burn --dry` discipline in real use.

## 1.3.0 — 2026-10-25 (T&E pass 2)
- **Safety: same-second backup collision** — two `modify` logs on one file within the same second overwrote each other's backup, so burn restored the INTERMEDIATE state instead of the original. Backup names now use microsecond precision with a collision loop. (Found in adversarial T&E; silent correctness failure.)
- **Safety: unknown/typo'd actions refused at log** — `log creat …` used to be recorded as a noted-only line, silently disabling reversal for that file with no warning.
- **Safety: `keep` is scoped to YOUR session dir** — it could previously move another live session's staged file into your outbox (steal + orphaning its ledger).
- **Integrity: a failed backup logs NOTHING** — unreadable files/dirs aborted with a raw traceback after… (now: clean error, partial backup discarded, no ledger entry, so no un-restorable action is ever recorded).
- **Crash-robustness: ledger merge** — main + `.bak` are now merged and deduped at burn instead of first-non-empty-wins, so a torn half-written line can't cost you a reversal.
- Packaging: `platforms: [linux]` frontmatter (shred/tmpfs/`/run/user` assumptions).
- selftest.sh extended: typo-action, cross-session keep, same-second collision regressions (39 assertions, both modes).

## 1.2.0 — 2026-10-25 (T&E hardening)
- **Safety: mis-logged `create` no longer destroys pre-existing files.** Logging `create` on a path that already exists is auto-demoted to `create_over_existing` — backed up at log time, RESTORED (not deleted) at burn. (Found in adversarial T&E: previously shredded user data.)
- **Safety: protected roots refused at LOG time** — `/`, `/home`, `~`, `/tmp`, `/var`, all top-level dirs, `/run/user/N`: logging any action against them now dies immediately (previously a typo'd path was *backed up* first — a /tmp copy-storm — and only the delete was guarded).
- **Safety: empty/whitespace targets refused** (no more cwd-resolution → recursive-shred-of-cwd hazard).
- **Safety: reverse-delete of a non-empty directory is skipped** with a warning at burn (unknown third-party content is never deleted).
- Backups: custom copier skips sockets/FIFOs/devices (previously crashed on e.g. X11/socket dirs), preserves symlinks, refuses >20k-file / >2GiB trees, >2GiB single files.
- `modify`/`delete` now require the target to exist (mis-use guidance in error).
- selftest.sh extended with the T&E regression cases (empty target, /tmp refusal, create-over-existing restore).

## 1.1.0 — 2026-10-25
- Added **RAM mode**: `incog.py open --ram` roots the session in `/run/user/$UID/incognito/` (tmpfs); refuses to start unless the path is verified tmpfs.
- `keep` outbox now follows the session's medium (RAM sessions never spill to disk on extract).
- `list` tags RAM sessions; burn/search work across both roots.
- Self-test (`scripts/selftest.sh`) covering create/modify-backup/dry-run/keep/burn reversal in both modes.
